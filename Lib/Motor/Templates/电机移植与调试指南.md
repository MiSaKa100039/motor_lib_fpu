# 电机驱动移植与调试流程

本文档用于新板卡或新电机首次调试，合并 PWM、采样方向、电流环、开环拖动和角度源验证流程。调试前应先确认功率器件额定值、母线供电能力和紧急关断方式。

## 1. 配置职责边界

### BSP 层

`BSP_Motor.cpp` 负责板级硬件事实：

- PWM 输出实际对应物理 `U/V/W` 的关系。
- ADC 外设、引脚、Rank 与物理 `U/V/W` 电流通道的关系。
- 哪些相电流传感器实际安装在板卡上。
- ADC 触发时刻是否适合本板采样拓扑。

电流读取接口位置固定代表物理相：

```cpp
read_currents_raw(uint16_t* raw_u,
                  uint16_t* raw_v,
                  uint16_t* raw_w,
                  uint16_t* raw_bus);
```

示例：U/V 双采样板卡。

```cpp
*raw_u   = ADC_U_VALUE;
*raw_v   = ADC_V_VALUE;
*raw_w   = 0U;          // 未安装，DUAL_SENSOR 时由库重建
*raw_bus = 0U;          // 未安装母线电流采样

.phase_current_valid_mask =
    Lib_Motor::MOTOR_PHASE_CURRENT_U_VALID |
    Lib_Motor::MOTOR_PHASE_CURRENT_V_VALID,
```

示例：U/W 双采样板卡。

```cpp
*raw_u   = ADC_U_VALUE;
*raw_v   = 0U;
*raw_w   = ADC_W_VALUE;

.phase_current_valid_mask =
    Lib_Motor::MOTOR_PHASE_CURRENT_U_VALID |
    Lib_Motor::MOTOR_PHASE_CURRENT_W_VALID,
```

`0U` 只是未安装通道的占位返回值。核心根据 `phase_current_valid_mask` 判断缺失相，不依据 ADC 数值猜测硬件是否存在。

### Platform 层

`Platform_Motor.cpp` 负责用户可调参数：

- 传感器换算参数，例如分流电阻、放大倍数或霍尔灵敏度。
- `DUAL_SENSOR` 或 `TRIPLE_SENSOR`。
- 已由 BSP 对应到物理相之后的电流符号翻转。
- 滤波、保护、控制环和电机参数。

```cpp
cfg.sensor.current_sense_mode = Lib_Motor::CurrentSenseMode::DUAL_SENSOR;

cfg.sensor.invert_phase_current_u = false;
cfg.sensor.invert_phase_current_v = false;
cfg.sensor.invert_phase_current_w = false;
```

Platform 不应再次配置 ADC 通道到 `U/V/W` 的映射。

### 角度源配置

- `Platform_MotorFeatures.h` 选择固件编译能力，宏值使用 `0/1`。
- 使用已完成的 `SMO` 时，先在该文件的“角度源编译能力选择”区将
  `LIB_MOTOR_ENABLE_SMO` 设为 `1`，再在 `Platform_Motor.cpp` 选择 `IF + SMO`。
- `cfg.observer` 是实例运行配置，不会自动启用 `LIB_MOTOR_ENABLE_*`；
  未编入或未实现的策略会在启 PWM 前报告 `OBSERVER_UNAVAILABLE`。
- `cfg.observer.startup_source` 选择启动/低速来源：`SENSOR`、`IF`、`HFI`。
- `cfg.observer.steady_source` 选择稳态控制来源：`SENSOR`、`SMO` 或预留高级观测器。
- `SENSOR + SENSOR` 表示有感直接闭环；`IF + SMO` 表示无感强拖后接管。
- `redundant_rotor_sensor` 是同轴冗余编码器；`output_sensor` 是减速器输出轴编码器，启用时填写减速比。
- `enable_redundant_observer_check` 与 `redundant_observer_source` 为无感影子观测器预留配置；
  当前开启会返回 `OBSERVER_UNAVAILABLE`，不能用作传感器失效接管。
- 当前主传感器运行故障按 `sensor_fault_action=STOP` 处理，并分别锁存
  `SENSOR_LOSS` 或 `SENSOR_SIGNAL_ERROR`，不是不带原因的通用 `Error`。

## 2. 支持的电流采样拓扑

### 双相电流采样

当前库支持任意两相实测，缺失相由 KCL 重建：

| BSP 有效相掩码 | 库重建量 |
| --- | --- |
| `U_VALID | V_VALID` | `Iw = -(Iu + Iv)` |
| `U_VALID | W_VALID` | `Iv = -(Iu + Iw)` |
| `V_VALID | W_VALID` | `Iu = -(Iv + Iw)` |

### 三相电流采样

三路相电流均实际存在时：

```cpp
cfg.sensor.current_sense_mode = Lib_Motor::CurrentSenseMode::TRIPLE_SENSOR;

.phase_current_valid_mask = Lib_Motor::MOTOR_PHASE_CURRENT_ALL_VALID,
```

此时 `raw_u/raw_v/raw_w` 全部必须来自真实 ADC 通道，库不会重建缺失相。

### 单电阻采样

当前库不支持单电阻 FOC。

- 仅测一相电流不能唯一计算另外两相电流，因此不能直接得到可靠的 `Id/Iq`。
- 常见的母线单电阻方案需要根据 SVPWM 扇区，在一个 PWM 周期内安排多个采样点并重建相电流。
- 母线单电阻还需要最小采样窗口判断、极限占空比下的 PWM 重排或降额策略。

在未单独实现上述链路前，不应新增一个枚举并将单电阻当作双电阻使用。

## 3. 低侧采样与相线采样

### 低侧分流电阻

低侧分流电阻位于桥臂下管回路。采样值是否有效取决于采样瞬间对应低侧器件是否已导通，并且必须避开死区与开关噪声。

本工程当前通过 TIM1 CH4 在 PWM 顶端附近触发 ADC。对于低侧采样，首次调试和高占空比运行时都应确认：

- 采样点处于有效低侧导通窗口。
- 采样窗口宽度覆盖运放建立时间和 ADC 转换时间。
- 接近调制极限时不会因窗口过短而产生错误电流反馈。

### 相线电流传感器或霍尔传感器

相线中的双向传感器通常可以在更多 PWM 状态下测得物理相电流，对低侧导通窗口的依赖较小。其相电流正负方向判定和 `Id/Iq` 变换规则仍然相同。

### 是否需要在 Platform 配置采样位置

当前实现中无需新增 `LOW_SIDE` 或 `INLINE` Platform 配置，因为：

- `current_sensor_type` 已负责电流换算公式，例如分流电阻或霍尔。
- ADC 触发时序与物理通道安装位置属于 BSP 硬件实现。
- 当前库尚未依据采样位置自动改变 PWM 或 ADC 触发策略。

如果后续要由通用库自动计算低侧有效窗口、重排 PWM 或支持母线单电阻，则应新增明确的采样拓扑/位置类型，并建立相应调制与采样策略。

## 4. 调试安全设置

首次上电前：

1. 使用可限流电源并将电流限制设置到测试所需的低值。
2. 将软件 `cfg.limit.max_current_a` 降到安全调试范围。
3. 只启用一种 `USER_MOTOR_TEST_*` 模式。
4. 手动 PWM 测试时从极小电压差开始，并准备立即停机。
5. 记录母线电压、相电流、故障状态和 PWM 输出。

常用命令：

| 命令 | 动作 |
| --- | --- |
| `CMD = 1` | 启动当前选中的测试模式 |
| `CMD = 2` | 滑行停机 |
| `CMD = 3` | 低侧制动 |
| `CMD = 4` | 清除锁存故障 |

### 调试模式配置文件放置

`USER_MOTOR_TEST_*` 表示当前应用要运行哪一种台架实验，应放在
`UserAPP/User_MotorTestConfig.h` 这样的应用层专用头文件中，而不是放入
通用电机库、BSP 或仅定义在 `Usermain.cpp`。

推荐职责划分：

| 文件 | 职责 |
| --- | --- |
| `UserAPP/User_MotorTestConfig.h` | 选择一个 `USER_MOTOR_TEST_*`；集中执行互斥及危险 API 开放检查 |
| `CMakeLists.txt` / IDE 调试 target | 只在 Debug 台架固件中定义 `LIB_MOTOR_ENABLE_DANGEROUS_TEST_API=1` |
| `Platform/Motor/Platform_MotorFeatures.h` | 集中选择传感器/观测器编译能力；危险 API 缺省保持关闭 |
| `Platform/Motor/Platform_MotorTestConfig.cpp` | 保存台架所需的 duty、电流及 VF/IF 分段参数 |
| `UserAPP/Usermain.cpp` | 根据已选择的模式响应命令并调用 API，不拥有全局编译开关 |

宏不能只放在 `Usermain.cpp`，因为 `Platform_Motor.cpp` 需要它选择
`startup_target_mode`，`Platform_MotorTestConfig.cpp` 也需要它决定编译哪组
测试参数。互斥 `#error` 与危险 API `#error` 应和宏选择放在同一头文件中，
使所有使用这些宏的翻译单元得到同一份检查结果。

Release 固件中如果仍保留任一 `USER_MOTOR_TEST_*`，构建应被 `#error` 拒绝；
这是防止将手动发波或锁轴接口带入发布固件的安全检查，不应绕开。

### 正常控制模式实现边界

`Platform_StartupTargetMode()` 中的 `VELOCITY_CONTROL` 是当前应用对正常启动的
默认意图，`start()` 也会请求这一模式；它并不表示所有闭环模式均已完成。

该配置项适合表示可持续运行的应用目标模式：可选择
`TORQUE_CONTROL`、`VELOCITY_CONTROL` 或 `POSITION_CONTROL`。其中速度/位置
级联环已经接入基础链路，但仍需要台架整定、默认目标初始化策略和验收测试。
`CALIB_RL_IDENTIFY`、`CALIB_ENCODER_OFFSET` 属于一次性
校准/辨识命令，应由专用 API 显式发起；制动应通过 `stop(StopMode)` 指定；
`DEBUG_*` 只允许由台架测试宏映射，不作为发布固件的默认业务模式。
目前修改 `startup_target_mode` 不会改变 `MotorAPI::start()` 的固定
`VELOCITY_CONTROL` 请求；需要运行转矩模式时应显式调用 `setTargetTorque()`。
其中 `startRLIdentification()` 已有入口但当前 FSM 暂复用锁轴过程，
`CALIB_ENCODER_OFFSET` 尚无 API/FSM 执行链，两者都不能按完成的校准功能验收。

未来让默认目标模式真正驱动 `start()` 时，还需要同时完成：

| 位置 | 必须修改的内容 |
| --- | --- |
| `MotorAPI::start()` / `MotorManager` | 读取只读的配置默认运行模式，并继续经过模式切换安全检查 |
| 启动模式校验 | 只接受已实现的 `TORQUE/VELOCITY/POSITION`；拒绝 `DEBUG/CALIB/BRAKE` |
| 默认目标初始化 | 速度默认启动要定义初始 `target_rpm`；位置默认启动要定义“保持当前位置”还是外部下发目标 |
| 位置反馈策略 | 当前为主转子单圈机械角；多圈/输出轴位置闭环需补累计或输出轴反馈 |
| 测试规划 | 验证各默认模式启动、非法模式拒绝、debug/calib 到普通模式不得直接跳转 |

当前实现状态：

| 模式 | 当前状态 |
| --- | --- |
| `TORQUE_CONTROL` | 已有角度反馈下的 d/q 电流环，可由 `setTargetTorque()` 给出 `Iq` 目标 |
| `VELOCITY_CONTROL` | 基础速度 PI 已接入，输出 `Iq` 目标；仍需按电机整定 |
| `POSITION_CONTROL` | 基础单圈位置 PI 已接入，输出目标转速；要求主位置传感器有效 |

因此不应仅凭编译通过就把 `start()` 或 `setTargetPosition()` 作为产品级
速度/位置闭环验收；必须完成限幅、目标初始化和台架整定后再开放默认启动入口。

## 5. 推荐测试顺序

| 顺序 | 模式 | 目标 |
| --- | --- | --- |
| 1 | 静态检查 | 母线、电流零偏、故障输入合理 |
| 2 | `USER_MOTOR_TEST_PWM_MANUAL` | 验证桥臂输出、相位映射和采样符号 |
| 3 | `USER_MOTOR_TEST_VF_CONTROL` | 验证开环旋转、电流波形和相序 |
| 4 | `USER_MOTOR_TEST_CURRENT_LOCK` | 验证 `Id/Iq` 闭环方向和 PI 参数 |
| 5 | `USER_MOTOR_TEST_IF_CONTROL` | 验证开环角度加电流闭环拖动 |
| 6 | 角度源/闭环 | 验证编码器或已实现的观测器路径 |

## 6. PWM Manual 与电流方向判断

### 测试目的

`DEBUG_PWM_MANUAL` 直接设置三相占空比，不依赖 FOC 电流环。该模式用于确认：

- PWM 的 `U/V/W` 桥臂映射。
- BSP 中 `raw_u/raw_v/raw_w` 的物理相映射。
- 实测相的电流符号。
- 双采样重建相是否与两路实测结果一致。

### 测试方法

连接电机时，使用低母线能量或严格限流，从极小相间电压开始。对当前 PWM 形式，可将两相保持为低占空比，只对一相增加很小的 `delta`：

```text
U 测试: U = delta, V = 0,     W = 0
V 测试: U = 0,     V = delta, W = 0
W 测试: U = 0,     V = 0,     W = delta
```

`delta` 必须从极小值开始，并短时间观察。

定义正相电流方向为“逆变器桥臂输出流向电机绕组”，则物理预期为：

| 发波相 | `Iu` | `Iv` | `Iw` |
| --- | ---: | ---: | ---: |
| U | 正 | 负 | 负 |
| V | 负 | 正 | 负 |
| W | 负 | 负 | 正 |

### U/V 双采样的重点判断

若 BSP 声明为 U/V 双采样：

```text
Iw = -(Iu + Iv)
```

则 W 发波时软件预期为：

```text
i_a < 0
i_b < 0
i_c > 0
```

`i_c` 是重建值，不能通过翻转 `invert_phase_current_w` 修正。若 W 测试错误，应检查：

- U/V 两路实际采样符号。
- BSP 输出位置是否确实是物理 U/V。
- PWM 的 W 指令是否实际驱动了 W 桥臂。
- 采样时刻是否处于低侧有效窗口。

### 是否必须使用电流钳

软件波形可以完成内部一致性检查，例如：

- 三相和是否接近零。
- 双采样重建值是否符合 `Iw = -(Iu + Iv)`。
- 某个控制命令是否导致固定方向的反馈发散。

但软件波形无法独立证明物理映射和量纲正确。例如 PWM 的 V/W 与 ADC 的 V/W 同时接错，软件内部可能仍显示自洽。首次板级调试中，至少需要一种外部物理基准：

- 电流钳；
- 串联的已校准电流测量设备；
- 可安全测量的采样电阻电压与已知换算关系。

因此：

- 首次确认采样极性、幅值和保护阈值时，外部测量应视为必需。
- 在同一硬件已经完成标定后，日常回归可主要依据软件波形判断。

## 7. VF Control

`DEBUG_VF_DRAG` 使用开环旋转电压矢量，不依赖电流环 PI。它用于在进入电流闭环前确认电机能够低能量平稳旋转，并观察三相电流形态。

建议：

1. 从仅启用第一段低速、低占空比曲线开始。
2. 确认无异常过流、母线下降或机械冲击。
3. 观察三相电流是否平衡、无明显零偏或异常畸变。
4. 每次只增加一个启动阶段。

若电流方向或 BSP 相映射仍有疑问，不应继续进入 Current Lock。

## 8. Current Lock

在 PWM 和采样路径可信后，使用 `DEBUG_CURRENT_LOCK` 验证 d/q 闭环方向。建议最初关闭积分项或使用很小积分，并从低电流开始：

```cpp
Platform_TestCurrentLockId = 0.2f;
Platform_TestCurrentLockIq = 0.0f;
```

依次测试：

| 步骤 | `Id_ref` | `Iq_ref` | 预期 |
| --- | ---: | ---: | --- |
| 1 | 正小值 | 0 | `Id` 同方向响应，`Iq` 接近零 |
| 2 | 负小值 | 0 | `Id` 反向响应，`Iq` 接近零 |
| 3 | 0 | 正小值 | `Iq` 同方向响应，可能出现正向转矩 |
| 4 | 0 | 负小值 | `Iq` 反向响应，转矩方向反转 |

异常处理：

- 目标为零但某轴在加入 `Ki` 后持续加速发散：优先检查反馈符号和相映射，而不是继续增加 PI 参数。
- 给一个轴指令，另一个轴出现大幅响应：检查相序、采样符号、电角度零点或 Park/Clarke 坐标关系。
- 纯比例环存在静差是正常现象；积分项只能在闭环方向正确后加入。

## 9. IF、角度传感器与无感功能

`DEBUG_IF_DRAG` 用于验证开环角度加电流闭环的拖动能力。进入此步骤前必须完成 PWM、采样与 Current Lock 验证。

有感闭环在启用前需要确认：

- 原始位置值有效且连续。
- 正反转方向与控制约定一致。
- 极对数和电角度偏置正确。

当前工程中：

- `SMO` 代码路径存在，但是否编译/启用由功能配置决定。
- `HFI` 和融合观测路径仍未形成可执行控制实现。
- 单相或母线单电阻在没有完整重建算法时，不能用于可靠的 `SMO/HFI` 输入。

## 10. 建议监测量

调试阶段至少记录：

```text
i_a, i_b, i_c
i_alpha, i_beta
i_d, i_q
target_id, target_iq
v_d, v_q
duty_a, duty_b, duty_c

```

| --- | ---: | ---: | ---: | --- | --- |

| V 发波 |  |  |  |  |  |

## 11. 完成条件

仅当以下条件全部满足后，才应逐步提高电流或启用完整控制路径：

- BSP 的 PWM 相映射和 ADC 相映射已依据硬件确认。
- `phase_current_valid_mask` 与真实安装通道一致。
- 外部测量已验证实测相的方向和幅值。
- 三相重建/求和关系合理。
- Current Lock 中 d/q 两轴均为负反馈且无发散。
- 保护阈值、限流电源和紧急停机均已验证。
