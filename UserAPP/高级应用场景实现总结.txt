高级应用场景实现总结(给 Codex 用)
========================================

## 一、整体阶段背景

针对高级应用(3D 打印机 XY、贴片机、机械臂关节、机器狗关节), 在原有单轴 FOC lib 基础上分阶段推进:

- Phase 1(架构转型): 删除原 TaskFSM 的"任务/队列"语义, 引入 writeSetpoint 流式 API + StreamState 流临停状态机。
- Phase 2(能力升级): BuildCfg 控制模式能力原子 + 位置环接通 + 速度前馈 + IMPEDANCE 占位 + HELD 占位 + FIFO/trigger 占位。
- Phase 2.5(收尾): 修 MotorAPI::start() 漏 POSITION 入口的真 bug + 文档化 + TODO 标签。
- 当前已生成: 由用户在 UserAPP/App/ 自行加了应用层协调骨架(Core/Axis/Motion/Energy/Sync)。


## 二、已实现的功能(高级应用相关)

### 1. lib API 层(Lib/Motor/Public/Motor_API.h)

- 流式核心 API MotorAPI::writeSetpoint(const MotionSetpoint&) — 每拍覆盖无任务无完成判据, 多轴同步由此 API 入口
- 语法糖 3 个 setTargetTorque/Speed/Position — 等价单字段 writeSetpoint
- Phase 3 分布式同步占位 API appendSetpointSeg/triggerSegPlayback/abortSegPlayback — 永远返 NotSupported
- 查询/调参/校准/调试 API — selectMode/getState/getFault/getMonitorData/setPIDGains/setRunPolicy/startRLIdentification/lockDebug 等 38 个公共 API
- Phase 2 调用顺序约束 — writeSetpoint 仅写 ctx_ 不切 mode, 上层必须先 selectMode → start → writeSetpoint

### 2. lib 控制环(Lib/Motor/Core/Runtime/Motor_ManagerRuntime.cpp)

- 位置环已接通:
    pos_err = target_pos_rad - angle_mech_sensor
    speed_ref = pid_position.update(pos_err) + vel_ff_rad_s * vel_ff_gain  (BuildCfg 双闸控)
    speed_ref_limited = limitSpeedReference(speed_ref)
    speed_err = speed_ref_limited - speed_rpm
    iq_ref = pid_speed.update(speed_err)

- 堵转保护在位置环也生效(与 VELOCITY_CONTROL 同走 updateStallProtection)
- IMPEDANCE 控制环占位: BuildCfg 开启时编进固件, 但 iq_ref=0。Phase 3 接通公式
    iq_ref = K*(pos_ref-θ) - D*(-ω) + torque_bias + torque_ff, 钳位 ±torque_limit

### 3. lib 数据结构

- MotionSetpoint { mode, pos_ref, vel_ff, torque_ff, stiffness, damping, torque_bias, torque_limit, hold_when_idle }
  9 字段覆盖 TORQUE/VELOCITY/POSITION/IMPEDANCE 四模式
- MotorFeedforwardParam { enable_vel_ff, enable_torque_ff, vel_ff_gain, torque_ff_gain } — 前馈通道运行期开关
- MotorImpedanceParam { default_stiffness, default_damping, torque_bias_default, max_torque_a } — Phase 3 默认值占位
- MotorPhysicalParam 加 load_inertia / gear_ratio / torque_constant — 机器狗/机械臂预留
- PlaybackTrigger { IMMEDIATE, AWAIT_SYNC } — Phase 3 触发语义定义
- StreamState { NONE, ACTIVE, SUSPENDED_BY_FAULT, SUSPENDED_BY_USER, HELD, FAULTED_LATCHED } — 取代旧 TaskState

### 4. lib 状态机

- Motor_StreamFSM 取代旧 Motor_TaskFSM, 描述流临停状态
- ACTIVE → SUSPENDED_BY_FAULT 在 fault 注入时
- ACTIVE → SUSPENDED_BY_USER 在 stop()/emergencyStop()
- ACTIVE → HELD 在 buildcfg HOLD 开启时距 last_setpoint_tick 超 hold_timeout_ticks
- 配套 MotorMotionParam.hold_timeout_ticks 字段

### 5. lib BuildCfg 能力原子(Platform/Motor/BuildCfg/Platform_MotorBuildCfg.h)

- 控制模式: MOTOR_BUILD_ENABLE_TORQUE/VELOCITY/POSITION/IMPEDANCE_CONTROL
- 前馈通道: MOTOR_BUILD_ENABLE_VELOCITY/TORQUE_FEEDFORWARD
- 流持仓安全: MOTOR_BUILD_ENABLE_STREAM_HOLD_WHEN_IDLE
- FIFO 回放: MOTOR_BUILD_ENABLE_SETPOINT_FIFO_PLAYBACK(Phase 3 占位)
- BuildCfg 顶部提供 能力原子 ↔ 产品形态 对照表(风扇/EV/打印机/机械臂/机器狗/分布式多 MCU)

### 6. lib 编译期裁切

- Motor_FeatureRegistry::supportsMode(Mode) 按 BuildCfg 返回 true/false
- MotorCommandGuard::validateModeSelection 拒 BuildCfg 关闭的模式
- Motor_LifecycleFSM::classifyStartRequest 接 POSITION/IMPEDANCE 进 Control
- MotorAPI::start() switch 分派 POSITION/IMPEDANCE 入口(Phase 2.5 修复)
- computeIqReference 位置分支用 #if LIB_MOTOR_ENABLE_POSITION_CONTROL 包, IMPEDANCE 分支用 #if LIB_MOTOR_ENABLE_IMPEDANCE_CONTROL 包

### 7. Templates/Coordinator/(lib 之外的应用范例)

- SyncedAxisGroup_Template.h/cpp — 分布式主机端协调器抽象基类 + CommBus 纯虚接口 + AxisHandle(LocalAxis/RemoteAxis)
- DualAxisSinDemo.h — 双轴 sin/cos 圆轨迹 demo, 验证 XY 走斜线/圆
- README.md — 调用序与形态讲解(单 MCU vs 多 MCU 分布式)

### 8. UserAPP/App/(用户自建应用层骨架)

- App_BuildConfig.h — App 自有裁切开关(USERAPP_ENABLE_SETPOINT_STREAM/MOTION/ENERGY/SYNC_COORDINATOR), 与 lib BuildCfg 解耦
- App_Core/AppCommand + AppCommandInbox — 通信层只-post 主循环消费的工业纪律
- App_AxisService — 包装 MotorAPI, cache setpoint + tickMotionStream 重写每拍(配合 lib HELD)
- App_MotionCoordinator — 多轴单 MCU 同 tick 分发 writeSetpoint
- App_EnergyCoordinator — BMS/制动电阻/回收比例 → lib setEnergyBudget 10Hz 刷新
- App_SyncCoordinator — 预加载帧 FIFO + trigger_tick + 1kHz 回放, 单 MCU 同步可用, 多 MCU 路径待 Phase 3 接 CommBus

## 六、关键架构原则(用户对话中确立)

1. lib 单轴边界永不破: 不能在 lib 内调多 MotorAPI 实例引用其他轴。多轴同步在 Coordinator 层。
2. BuildCfg 按能力原子裁切, 不按产品名: 一个 BuildCfg 组合可同时服务多产品。
3. 前馈建模完全在主机层: lib 的 VELOCITY_FEEDFORWARD 开关仅是 通道接入 开关, lib 做一行加法不做决策。
4. 多轴同步两种形态:
   - 单 MCU 多实例(风扇类): Coordinator 同 ISR tick 调多次 writeSetpoint
   - 多 MCU 分布式(打印机/机器狗): 每轴一块 MCU 独立 lib, 经 CAN/EtherCAT 预加载 setpoint 段 + SYNC 触发
5. TaskFSM 已退役: 改为 StreamState 描述流临停, 解耦 任务 与 流 概念。
